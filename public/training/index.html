组件之间怎样传数据？App 把 model 作为 props 传给画面，例如 <FormPage model={model} />。画面通过 model 读取项目、更新草稿和执行保存；各 TSX 文件有清楚的职责。

1

技术点讲解

可以把 state 理解成界面的小记事本。tab 记住“当前打开哪一页”。点击菜单时只更新这个值，setTab 会通知 React 更新 App；App 再次执行时会读到新的 tab，然后执行我们写在 JSX 中的条件判断。React 并不认识“tab”这个名字，也不会自己猜测它对应哪一页，页面切换规则是我们在 App.tsx 中写出来的。

为什么更新 tab 就能切换画面？按这 5 步看

  1. 点击菜单：“输入与校验”的 id 是 form，点击回调执行 setTab("form")。
  2. 通知 React：setTab 是 useState 提供的更新方法。React 安排一次更新；它可以合并同一事件中的多次状态更新，并非立刻改写当前函数里的 tab 变量。
  3. 重新计算 JSX：React 再次执行 App 组件；这一次 useState 返回的新 tab 是 "form"。共享数据由 Hook 的状态保留，不会因为函数再次执行就全部清空。
  4. 重新判断条件：tab === "grid" 为 false，表格分支不显示；tab === "form" 为 true，于是 JSX 返回 <FormPage model={model} />。
  5. 更新实际画面：React 比较前后渲染结果，再提交必要的 DOM 更新。此例中 GridPage 会卸载，FormPage 会挂载，公共菜单与布局继续保留。无需刷新整个网页。
App 计算时的 tab条件判断最终显示
"grid"tab === "grid" 为 trueGridPage（项目工作台）
"form"tab === "form" 为 trueFormPage（输入与校验）
"tree"tab === "tree" 为 trueTreePage（组织与导航）

关键点：React 负责“收到状态更新后重新渲染”；我们写的条件表达式负责“根据 tab 选择哪一个画面”。把文件改名、或者只给普通变量赋值，都不会自动建立这条切换规则。

useState保存一个会变化的值，并提供更新它的方法。
JSX 条件渲染条件为 true 时，才显示对应组件。

数据绑定：把数组交给表格显示

本课目标：浏览器怎样发送 API 请求，模拟服务怎样返回 JSON，结果又怎样进入表格？

① 技术点讲解→② 对应代码→③ 对应画面
1

技术点讲解

现在浏览器真正发送 HTTP 请求。App 提交初始界面后，Effect 等待 300ms 防抖，再调用 API 客户端 loadProjects，客户端通过 fetch 请求本机 /api/projects。Vite 中的模拟服务返回 JSON；前台检查 HTTP 状态、解析响应并恢复日期类型，再把 response.data 写入 view.sourceCollection，FlexGrid 随之显示项目。

本例现在有一条真实的请求与响应链路

浏览器 → GET /api/projects → Vite 本地模拟 API → HTTP 状态与 JSON → 前台解析 data → view.sourceCollection → FlexGrid。

1. API 在哪里？数据在哪里？

本地 API 的实现是 server/mockApi.ts，由 vite.config.ts 注册到 Vite 的开发服务和 preview 服务。启动工程时，模拟服务调用 makeProjects() 创建 120 条项目，放在服务端内存里。前台不再通过定时器直接生成加载结果，也不从 localStorage 恢复项目列表。

2. 浏览器发出了什么请求？

GET /api/projects?fail=false&delay=600。fail 控制正常或故障响应，delay 控制模拟服务的等待时间。浏览器 Network 面板可以查看请求、状态码和响应体。前台通过 signal 将 AbortController 连接到真正的 fetch。

3. 模拟服务返回什么？

HTTP 200 OK
Content-Type: application/json
{
  "data": [
    { "id": 1, "name": "员工门户 001", "hours": 8, "start": "2025-12-31T15:00:00.000Z", "...": "其他项目字段" }
  ],
  "total": 120,
  "requestId": "每次请求生成的标识"
}

这是响应结构示意，data 实际包含全部项目，预览省略了其他记录和字段。日期是标准 JSON 字符串；时区转换后，画面以本地日期格式显示。

4. 收到响应不等于马上得到项目数组

  1. await fetch：得到 Response，其中有 status、ok 等 HTTP 信息。
  2. await response.json()：将响应体解析为 JavaScript 对象。当前服务无论成功还是故障均返回 JSON。
  3. 检查 HTTP 状态：HTTP 500 不会让 fetch 自动进入 catch；客户端主动抛出 ApiError，Effect 才会走失败流程。
  4. 检查响应与恢复类型：确认 data/total/requestId 结构，将 start 的字符串转换成 Date 并执行业务校验。
  5. 交给视图：loadProjects 返回响应对象，Effect 读取 response.data，再赋值 view.sourceCollection。

5. 画面在什么时候显示数据？

阶段数据动作画面
首次计算与提交创建空 view，GridPage 绑定它初始可显示加载提示、列头和空数据区
Effect 启动请求loadProjects → fetch → 本地 API继续等待，保存暂不可用

view 是稳定的数据视图对象，response.data 是 API 返回的匹配项目数组，view.sourceCollection 持有全部源记录，view.items 是筛选和分页后的当前页记录。初始总数为 120，而默认每页为 15。

6. 保存、恢复和再次获取

保存通过 PUT /api/projects 提交 { rows, removedIds }；模拟服务校验后按 ID 合并并删除指定项目，保留其他记录，后续 GET 返回保存结果。恢复初始数据通过 DELETE。重启服务会重新生成 120 条初始记录；同一服务实例的多个浏览器共享数据。旧 localStorage 不自动迁移或上传。

这是一套用于培训的本机模拟 API，不连接公司的生产系统；无数据库、登录认证和并发冲突控制。使用 npm run dev 或 npm run preview 启动；仅把 dist 放到普通静态服务器上不会提供此 API。

每轮 Effect 创建自己的 controller，把 signal 交给 loadProjects，最终传入 fetch(url, { signal })。React 清理旧 Effect 时调用 abort。取消是浏览器请求的控制流程，普通 HTTP 故障则由 API 响应和错误处理决定。

正常完成

启动 loading → fetch 发送 GET → 模拟服务等待 600ms → HTTP 200 返回 JSON → response.ok 为 true → response.json() 解析 → 恢复 Date → then 写入 view.sourceCollection → 未取消的 finally 关闭 loading。

异常情况：服务返回 HTTP 500

服务返回 { error: { code, message }, requestId }。fetch 此时仍可能正常返回 Response，因此 requestProjects 必须检查 response.ok，并抛出 ApiError。Effect 的 catch 显示错误，finally 结束 loading，成功分支不改写 view。网络连接失败则可以直接导致 fetch 拒绝，也会进入 catch。失败不会自动重试；关闭故障开关或手动重试会启动新一轮。

主动取消：A 还没结束，又启动 B

  1. 用户再次请求，或修改 fail/delayMs，Effect 依赖改变；React 清理 A，调用 A.abort()。
  2. 浏览器 fetch 或尚未完成的响应体读取收到 signal，通常以 AbortError 拒绝。A 的 catch 不把它显示为系统故障；A 的 finally 检查到 signal.aborted，不会关闭 B 的 loading。
  3. B 使用新的 controller，负责自己的成功、失败和收尾。客户端还在解析后与写入前检查取消状态，避免取消的任务继续提交数据。
  4. 本地模拟服务监听响应连接关闭，若仍处于延迟等待，会清掉自己的定时器。这个配合只属于当前模拟服务；取消浏览器请求不保证真实后台工作停止，更不代表后台事务回滚。

FlexGrid 标签怎么用？先认识“表格、列、数据”

FlexGrid 是 Wijmo 提供的 React 表格组件。可以把它理解成一张可交互的表格：父标签设置整张表的行为，内部的 FlexGridColumn 定义每一列，itemsSource 提供行数据。它不是 HTML 原生标签，需要先 import 组件，并引入 Wijmo 样式。本工程在 main.tsx 统一引入样式，各页面无需重复引入。

4. initialized：什么时候能拿到表格实例？

React 创建并初始化 Wijmo 底层控件后，调用 initialized，把原生 FlexGrid 实例作为 g 传入。这里的 GridControl 是从 @mescius/wijmo.grid 导入的原生类类型别名，用于 TypeScript 检查；它不是另一个页面组件。不要写成 initialized={handleInitialized()}，那样会在渲染时立即调用函数；应传入函数本身或示例中的箭头函数。

grid.current = g 把实例存到 useRef，供后续用户操作使用，不会触发 React 重新渲染。initialized 对应控件初始化，不会在每次 API 返回、每次切换行或普通重新渲染时重复触发。切离本页导致组件卸载、再进入重新创建时，会得到新实例。

例如在同一个组件的按钮事件中调用 grid.current?.autoSizeColumns()，可按内容自动调整列宽；保存前调用 finishEditing 则用于提交当前编辑。本例将实例保存在共享模型中，所以页面卸载后不要继续调用旧控件；重新进入页面并完成 initialized 后再使用。读取 current 不需要等待一次新的 React 渲染。

5. 把使用过程连成一条线

  1. React 渲染 GridPage：把 view 和配置属性交给 FlexGrid，子标签描述列、筛选器和模板。
  2. Wijmo 创建并初始化控件，initialized 提供可操作的原生实例；初始 view 为空时，表格可以先显示标题与空数据区。
  3. API 成功后，Effect 更新 view.sourceCollection；表格读取各行字段，按 binding、format 和模板显示内容。
  4. 用户排序、筛选、翻页或编辑时，控件与同一个 view 协作，相关事件与模型逻辑处理变更。不是每一次操作都要重新请求 API。
